# 🎂 وثيقة تصميم ميزة: أمر الإنتاج اليومي المجمّع (Daily Multi-Product Batch Production)

**التاريخ:** 2026-11-26  
**الغرض:** تسريع إدخال الإنتاج اليومي في مصنع الحلواني (مئات التورتات والجاتوهات والحلويات الشرقية) من خلال شاشة واحدة تقبل عدة أصناف وكميات دفعة واحدة، مع الحفاظ الكامل على سلامة الجداول المحاسبية ودوال التصنيع الحالية.

---

## 1. المشكلة الحالية
- في الوضع الحالي (`modules/manufacturing/components/ManufacturingManager.tsx`), يرتبط كل أمر تشغيل في `work_orders` أو `mfg_production_orders` بـ `product_id` واحد فقط.
- إدخال الإنتاج اليومي (مثل 400 تورتة + أصناف الجاتوه + الشرقي) يضطر المستخدم لتكرار العملية لكل صنف على حدة.

---

## 2. الحل المعتمد (دون تغيير بنية قاعدة البيانات الحالية)
إضافة شاشة جديدة متخصصة: **"أمر الإنتاج اليومي المجمّع" (`DailyBatchProduction.tsx`)**:

1. **جدول أصناف متعدد الصفوف:**
   - اختيار أكثر من منتج تام / نصف مصنع (`ProductSearchSelect`) + الكمية المنتجة + المستودع المستهدف + تاريخ الإنتاج.
   - إمكانية إضافة/حذف صفوف، أو تحميل تصنيف كامل (مثل: تورتات، جاتوهات، حلويات شرقية) دفعة واحدة.
2. **قوالب الإنتاج اليومية (Saved Shift Templates):**
   - حفظ قائمة الأصناف المتكررة يومياً كقالب جاهز (مثلاً: *وردية الصباح — التورتات*)، بحيث يفتح المستخدم القالب يومياً ويعدّل الكميات فقط.
3. **فحص توفر الخامات المجمّع (Pre-Flight Availability Check):**
   - قبل التنفيذ، يحسب النظام إجمالي احتياج الخامات لجميع الأصناف المختارة من وصفاتها (`bill_of_materials` / `mfg_routings`) دفعة واحدة ويعرض أي عجز محتمل بوضوح.
4. **التنفيذ التلقائي بمرجع دفعة موحد:**
   - عند الضغط على **"اعتماد وتصنيع الكل"**، يولّد النظام مرجعاً موحداً للدفعة (مثل `DAILY-BATCH-YYYYMMDD-XXX`) ويُنشئ/ينفّذ في الخلفية أوامر الإنتاج والقيود المحاسبية وخصم الخامات وإضافة الإنتاج التام لكل صنف بالتوازي المحكوم أو بالترتيب الآمن.
   - استخدام نفس دوال الإنتاج المعتمدة في النظام للحفاظ على دقة التكلفة المرجحة (`WAC`) وإعادة احتساب المخزون.

---

## 3. ضوابط الأمان وخطة التنفيذ غداً
1. **عدم تعديل الجداول أو دوال الـ RPC الحالية** حتى لا تتأثر تقارير التكلفة أو `schema-guard`.
2. **تفعيل قفل `useRef`** لمنع الإرسال المزدوج أثناء تنفيذ الدفعة.
3. **الاختبار أولاً على البيئة المعزولة (`.env.test` / `preview`):**
   - إضافة اختبارات وحدة تتحقق من حساب إجمالي الخامات ومنع الإرسال المزدوج وحفظ القوالب.
   - تشغيل `npm run schema-guard` و`npm test` و`npm run build` قبل الدمج في `main`.
