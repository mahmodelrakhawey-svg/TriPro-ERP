# 🗄️ تحديثات وتعديلات قاعدة البيانات (Database Updates)

> **قاعدة بيئة التطوير المعزولة:**
> نحن نعمل في بيئة تطوير معزولة. أي تعديلات تخص جداول أو دوال أو سياسات أو إجراءات قاعدة البيانات **لا تُطبَّق مباشرة**، بل يتم وضع كود الـ SQL الخاص بها في ملف مستقل داخل هذا المجلد (`sql_updates`).

---

## 📌 اتفاقية تسمية الملفات (File Naming Convention)
يجب أن يبدأ اسم كل ملف بتاريخ اليوم متبوعاً باسم الميزة أو التعديل بصيغة واضحة:
```text
YYYY-MM-DD_<feature_name_or_fix>.sql
```

### أمثلة:
- `2026-09-07_add_inventory_batch_tracking.sql`
- `2026-09-07_fix_cost_closing_function.sql`
- `2026-09-07_user_roles_rls_policies.sql`

---

## 📝 هيكل ملف الـ SQL الموصى به:
يُفضّل أن يحتوي كل ملف على تعليقات توضيحية وهيكل آمن وقابل لإعادة التشغيل (Idempotent):

```sql
-- ==============================================================================
-- تاريخ التحديث: YYYY-MM-DD
-- الميزة / التعديل: [اسم الميزة / الغرض من الكود]
-- البيئة: بيئة تطوير معزولة
-- ==============================================================================

-- 1. عمليات التحقق أو إنشاء الجداول (إن وجدت)
-- CREATE TABLE IF NOT EXISTS ...

-- 2. الأعمدة الجديدة أو التعديلات
-- ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...

-- 3. الدوال والإجراءات (Functions / Triggers)
-- CREATE OR REPLACE FUNCTION ...

-- 4. سياسات الأمان وصلاحيات الوصول (RLS & Grants)
-- ALTER TABLE ... ENABLE ROW LEVEL SECURITY;
```
